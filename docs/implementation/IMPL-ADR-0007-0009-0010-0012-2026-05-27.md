## Decisões de implementação e desvios

### ADR-0007

**Versão do chart metrics-server:** `3.12.2`
- Versão consultada via Terraform MCP em 2026-05-27. Não havia módulo público verificado
  para metrics-server — adotado `helm_release` nativo conforme restrição do projeto.
- Versão do helm provider: `~> 3.0` (latest: `3.1.2` validado via MCP). A sintaxe do
  provider `helm` v3 usa blocos `kubernetes` como atributo (não nested block), e `set`
  como block list — isso difere da sintaxe helm v2. O código gerado usa a sintaxe v3 correta.
- O ADR especifica `resources: requests cpu=10m memory=20Mi / limits cpu=100m memory=100Mi`
  para t3.micro. Implementado conforme especificado (mais conservador que os valores do ADR
  que mencionam 50m/64Mi em outro trecho; os valores enxutos da instrução de missão foram
  adotados por serem mais adequados para o cluster t3.micro MVP).
- `--kubelet-insecure-tls` habilitado conforme instrução de missão (EKS requer). O ADR
  menciona "validar antes de habilitar" — comentário incluído no código explicando o contexto.
- `priorityClassName = system-cluster-critical` implementado conforme ADR.
- Rollback plan: `helm rollback metrics-server <revision> -n kube-system` (documentado em
  `rollback-helm-addons.md`).

### ADR-0009

**Jobs implementados:** 9 jobs (conforme ADR):
`secret-scan`, `iac-tf-scan`, `iac-k8s-scan`, `sast-frontend`, `sast-backend`,
`sca-frontend`, `sca-backend`, `container-frontend`, `container-backend` + `summary`.

**Desvio menor:** O ADR menciona `--audit-level=high` para npm audit que "não falha".
A implementação usa `--audit-level=critical` para bloqueio + `--audit-level=high` com
`|| echo "::warning::..."` para warning, alinhando com a política de severidade do ADR
(CRITICAL bloqueia, HIGH é warning).

**Paths de Dockerfile:** O CI/CD existente usa:
- Backend: `devops-ia-apps/backend/DevopsIaPlatformApi` (Dockerfile neste subdiretório)
- Frontend: `devops-ia-apps/frontend` (Dockerfile na raiz do frontend)
Esses paths foram usados nos jobs `container-*`.

**Semgrep:** `SEMGREP_APP_TOKEN` é opcional para uso da CE gratuita; o secret pode não
existir no repositório. Para uso sem token (rules públicas), a action pode rodar sem token
mas com funcionalidade limitada.

**Workflow `security-scheduled.yml`:** Usa `soft_fail: true` no Checkov e `exit-code: 0`
no Trivy para o scan agendado — permite gerar findings sem bloquear o cron quando não há
PR associado.

### ADR-0010

**Bucket `devops-ia-production-cluster-backups`:** O ADR especifica provisionamento via
Terraform. Um novo Terraform stack ou adição ao stack existente (`03-ci-cd-stack-ai` ou
`04-addons-stack-ai`) seria o local correto. Esta implementação **não cria o bucket**
por Terraform — o cluster-snapshot.md documenta o bucket e o workflow de backup está
documentado, mas o recurso Terraform não foi implementado. **Pendência:** criar
`cluster-backup.tf` em stack apropriada (sugestão: `04-addons-stack-ai` ou novo
`05-backup-stack-ai`).

**Workflow `cluster-backup.yml`:** Não criado nesta implementação — requer o bucket S3
provisionado e um IAM Role com OIDC para GitHub Actions com escopo de write no bucket.
**Pendência:** criar o workflow e o recurso Terraform do bucket.
